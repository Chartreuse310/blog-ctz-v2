## #1 重做计划：markdown-it 插件自动注入文章元信息

### 背景与上次的坑
上次用 `#doc-before` slot 注入，但它渲染在 H1 **上方**，破坏了 `H1 → meta → 正文` 的视觉顺序。调研确认：H1 是 markdown `<Content>` 内部的产物，**主题层面没有任何 slot 能落在"H1 下方、正文上方"**。所以正确的路是在 markdown 层注入。

### 已验证的关键事实（基于源码）
1. H1 由编译后的 markdown 产生，在 `<Content>` 内部，主题组件无法穿透。
2. VitePress 的 frontmatter 插件通过包装 `md.render`，在 markdown 真正解析**之前**就把 `env.frontmatter` 写好了（chunk-D3CUZ4fa.js:23122-23140）。
3. 因此我的 markdown-it 插件在渲染流程中执行时，`env.frontmatter` 已经就绪，可直接读取 date/author/tags。
4. 已有 `markdown-it-vextab.ts` 作为同模式先例。

### 实现方案（路径 A）
**新建 `docs/.vitepress/markdown-it-postmeta.ts`**：
- 用 `md.core.ruler.after` 钩子，遍历 token 流找到第一个顶层 `heading_open` + `heading_close`（即 H1）的闭合位置
- 在 H1 之后插入 `html_block` token，内容为 `<div class="post-info">...</div>`
- 数据来自 `env.frontmatter`：date（格式化 YYYY-MM-DD，兼容 YAML Date 对象）/ author / tags
- 守卫条件：仅当 `env.frontmatter.date` 存在时才注入（首页/关于页无 date，自动跳过）

**修改 `config.mts`**：
- 在已有的 `markdown.config: (md) => { md.use(vextabPlugin) }` 里追加 `md.use(postmetaPlugin)`

**删除 4 篇文章手写的 meta 块**：
- `why-i-play-guitar.md` / `vextab-usage-guide.md` / `how-i-prepared-for-lecture-with-llm-wiki.md` / `solution-z-knowledge-organization-method.md`
- 各删掉 `<div class="post-info">...</div>` 那一段，正文只保留 `# 标题` + 正文

### 复用与零样式改动
- 注入的 HTML 沿用现有的 `.post-info` / `.post-author` / `.post-tag` 类（custom.css 已定义），不新增 CSS
- meta 内容与原手写块完全一致，视觉零变化

### 不做的事
- 不改 DocLayout.vue / Outline.vue（与本次无关）
- 不动 PostList.vue（列表页逻辑不变）
- 不引入新依赖

### 验证方式
`npm run docs:build` 构建通过，并检查生成的 HTML：
- 4 篇文章页：`<h1>` 出现在 `<div class="post-info">` **之前**（顺序正确，这是上次失败的点）
- meta 内容（date/author/tags）正确，日期为 YYYY-MM-DD 格式
- about 页 / 首页：无 post-info 注入

### 风险评估
低风险。核心不确定性（markdown-it 能否拿到 frontmatter、能否精确插入 H1 之后）已通过源码验证。最坏情况退化为"meta 没注入"，不会破坏现有布局（大不了回到手写）。
