## #4 SEO 基础设施计划：sitemap + OG + RSS

基于源码与文档调研，三件事方案都已确定。站点 URL 确认为 `https://chartreuse310.github.io/blog-ctz-v2/`（无自定义域名，部署到 GitHub Pages 项目页）。采用最稳妥的默认决策：RSS 自写复用 createContentLoader、OG 全局默认图、cleanUrls 保持现状。

---

### 第一部分：Sitemap（零依赖，原生支持）

VitePress 1.6.4 原生支持 sitemap，配置 `sitemap.hostname` 后自动生成 `sitemap.xml`。

**改动**（config.mts，+4 行）：在 `lastUpdated: true` 后加：
```ts
sitemap: {
  hostname: 'https://chartreuse310.github.io/blog-ctz-v2/'
}
```

**陷阱处理**：调研确认 hostname 必须含 base 段 + 尾斜杠（`new URL(rel, hostname)` 解析规则），否则文章 URL 会丢失 `/blog-ctz-v2/` 前缀。已在注释里写明。

**验证**：构建后检查 `dist/sitemap.xml` 生成，URL 形如 `https://chartreuse310.github.io/blog-ctz-v2/posts/why-i-play-guitar.html`（含 base、含 .html）。

---

### 第二部分：OG / Twitter Card（transformHead 钩子，零依赖）

用 VitePress 的 `transformHead` 钩子批量生成 per-page OG meta，从现有 frontmatter 复用（title/excerpt/date/tags）。

**改动**（config.mts，~25 行）：新增 `transformHead(context)` 钩子：
- 只对文章页（`context.pageData.relativePath` 以 `posts/` 开头）注入 article 类型 OG
- `og:title` ← `frontmatter.title`
- `og:description` ← `frontmatter.excerpt`
- `og:type` = `article`，`article:published_time` ← `frontmatter.date`
- `og:image` ← 全局默认图（`/blog-ctz-v2/og/default.png`，暂用占位，后续可加 per-page）
- `og:url` ← hostname + 相对路径
- `twitter:card` = `summary_large_image`
- 非文章页（首页/about）注入 `website` 类型 + 站点级默认 OG
- 同时补一个站点级 `head` 默认值（`og:site_name`）

**og:image 占位**：不生成实际图片文件（需你后续设计），先用一个 `public/og/default.png` 的引用。如果文件不存在，分享时图片显示空白但不报错。我会标注 TODO 让你后续补图。

**验证**：构建后检查文章页 HTML 的 `<head>` 含 og:title/og:description/twitter:card，且内容随文章变化。

---

### 第三部分：RSS feed（自写 buildEnd + feed 包，复用 createContentLoader）

**改动**：
1. `npm i -D feed`（1 个小依赖，纯 RSS/Atom/JSON feed 生成）
2. 新建 `docs/.vitepress/rss.ts`：导出一个 `buildRSS(siteConfig)` 函数，内部用 `createContentLoader('posts/*.md')`（复用 posts.data.mts 同款逻辑）拿到文章列表，喂给 `feed` 包生成 RSS 2.0，写入 `dist/feed.xml`
3. config.mts 加 `buildEnd: buildRSS` 钩子

**复用单一数据源**：createContentLoader 与 PostList/posts.data.mts 同源，保证文章数据只有一处。

**验证**：构建后检查 `dist/feed.xml` 生成，含 4 篇文章的 title/link/description/pubDate。

---

### 不做的事
- 不开 cleanUrls（保持 .html，避免 GitHub Pages 404 风险）
- 不生成实际 og:image 图片（标注 TODO，需你设计）
- 不引入 vitepress-plugin-rss（自写更契合项目风格）

### 执行顺序与回退
按 sitemap → OG → RSS 顺序，每部分独立构建验证。任一部分出问题可单独回退（git checkout 对应文件）。RSS 涉及安装依赖，会单独确认。

### 风险评估
- sitemap：极低（1 行配置，原生功能）
- OG：低（transformHead 是官方钩子，不破坏现有 head）
- RSS：低-中（需新依赖，但 feed 包成熟；buildEnd 不影响页面渲染，最坏只是 feed 不生成）
