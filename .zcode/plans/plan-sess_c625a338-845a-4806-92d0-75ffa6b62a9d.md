## #2 修复计划：统一数据加载逻辑（路径 A）

**背景**：侧边栏列文章只是当初顺手填的（你已确认），并非有意设计。所以走路径 A——删掉侧边栏，只保留 `/posts/` 列表页这一套数据逻辑。

**已验证的关键事实**（通过源码确认）：
- aside（右侧目录）和 sidebar（左侧栏）是两个独立区域
- 删除 `themeConfig.sidebar` 后，左侧「近期文章」列表消失，但右侧自定义 Outline 组件继续显示
- 文章页布局不受影响，4 篇文章页、about 页、首页均无副作用

### 改动清单（全部在 config.mts，单文件）

**1. 删除 `getSidebarItems()` 整个函数**（config.mts 第 6-32 行）
- 移除自写的正则解析 frontmatter 逻辑（解决问题 1：脆弱的 YAML 解析）
- 移除 `——` 破折号截断标题逻辑（解决问题 2：隐式且不统一的标题处理）

**2. 删除不再使用的 import**（config.mts 第 2-3 行）
```ts
import { readFileSync, readdirSync } from 'fs'   // 删除
import { join } from 'path'                       // 删除
```

**3. 删除 `themeConfig.sidebar` 配置块**（config.mts 第 58-66 行）
```ts
sidebar: {
  '/posts/': [
    {
      text: '近期文章',
      link: '/posts/',
      items: getSidebarItems()   // 整块删除
    }
  ]
}
```

### 改动后的效果
- 文章数据只有**单一来源**：`createContentLoader`（PostList.vue + posts.data.mts），解决问题 3
- 侧边栏消失，读者通过顶部导航 `文章` 或首页进入 `/posts/` 列表页浏览文章
- 右侧目录（Outline）保留，阅读体验不降级
- config.mts 从 70 行精简到约 40 行，无 fs 操作、无正则

### 不做的事
- 不动 PostList.vue / posts.data.mts（它们是正确实现，保留）
- 不动 Outline.vue / DocLayout.vue（与本次无关）
- 不补 RSS/sitemap（那是 #4，单独处理）

### 验证方式
`npm run docs:build` 构建通过，并检查：
- 4 篇文章页 HTML 仍正常渲染、右侧 outline 存在
- `/posts/` 列表页 PostList 正常显示全部文章
- 侧边栏 DOM 不再生成

### 风险评估
低风险。删除的是冗余功能（侧边栏列表与列表页重复），且通过源码确认不影响 aside/outline。唯一"可见变化"是文章页左侧不再有文章列表——这正是预期的。
